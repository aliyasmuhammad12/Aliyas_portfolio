<Problem>

An AI summarization feature shipped quickly and became popular. Finance noticed OpenAI invoices climbing week over week. Engineering had **no per-route attribution** and no guardrails—every plan tier hit the same model.

{/* TODO: Add anonymized spend chart and peak traffic date. */}

</Problem>

<WhatWouldHaveBroken>

- Hard-switching every call to the cheapest model overnight (quality cliff, churn).
- Client-side API keys (already ruled out, but prototypes often tempt this).
- Blocking users silently when spend spiked instead of degrading gracefully.
- Logging full prompts with PII into a third-party tool without retention policy.

</WhatWouldHaveBroken>

<Approach>

- **Instrument first** — Middleware tagging each request with `feature`, `plan`, `model`, token counts, and USD estimate.
- **Route by task** — Classification step sends boilerplate to a mini model; long documents use chunked map-reduce.
- **Cache** — Redis keyed by normalized input hash + model version; TTL aligned with content freshness SLAs.
- **Budgets** — Soft caps per org with queued retries and user-visible "try again later" copy.

Example guard in a route handler:

```typescript
const budget = await getOrgBudget(orgId);
if (budget.remainingUsd <= 0) {
  return rateLimitedResponse();
}

const completion = await openai.chat.completions.create({
  model: selectModel(task, budget.tier),
  messages,
  max_tokens: budget.maxOutputTokens,
});
await recordUsage({ orgId, model: completion.model, usage: completion.usage });
```

</Approach>
