AI features often ship without a **cost owner**. Usage climbs, invoices spike, and the first fix is “turn it off.” These are the controls I add before scaling traffic.

## You cannot optimize what you do not measure

Log **model**, **input/output tokens**, **route/feature name**, and **estimated USD** per request. Finance and product should read the same dashboard.

```typescript
await recordUsage({
  feature: "summarize-ticket",
  model: completion.model,
  promptTokens: completion.usage?.prompt_tokens,
  completionTokens: completion.usage?.completion_tokens,
});
```

## Route models by task, not by habit

Defaulting everything to the largest chat model is the fastest way to burn budget. Classify the task, use a small model for routing and simple transforms, and reserve large models for high-stakes generation.

## Cache with explicit freshness rules

Hash normalized inputs plus **model version** and **prompt version**. TTL should match how stale an answer can be for that feature—support docs vs live inventory are different beasts.

## Budgets and kill-switches

- Soft caps per org or per user tier with graceful degradation.
- **Daily kill-switch** for anonymous or demo endpoints.
- Alerts before hard stops—not after the invoice closes.

## What not to do

- Client-side API keys (ever).
- Uncapped streaming to anonymous users.
- Logging full prompts with PII into third-party tools without retention policy.
