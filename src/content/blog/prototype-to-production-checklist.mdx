AI-generated prototypes optimize for **screenshots**, not **COGS**, **security**, or **on-call**. Use this checklist after the demo wins the room.

## Week 0 — Stop the bleeding

- Rotate any API keys that ever lived in the repo or client bundle.
- Move secrets to Vercel/AWS parameter store; document who can access prod.
- Delete unused routes and components—the generated tree is always bigger than you need.

## Week 1 — Identity and money

- Replace mock auth with NextAuth (or your IdP); protect server actions and route handlers.
- Stripe: Checkout + **webhooks** + idempotency table before marketing "paid plans."
- Map roles (`owner`, `member`, `billing`) to database rows, not JSX props.

## Week 2 — Data and types

- One source of truth schema (Prisma/Drizzle); ban duplicate interfaces copied from the prototype.
- Zod at API boundaries; never trust client-generated types from the builder export.

## Week 3 — Pipeline

- CI: `typecheck`, `lint`, `test`, `build` on every PR.
- Preview deployments per branch; seed script for demo data.
- Error monitoring (Sentry or similar)—TODO pick vendor and wire source maps.

## Signals you are not ready to launch

- No one can answer "what happens if Stripe webhook fires twice?"
- Lighthouse performance under 70 on the signed-in home route.
- OpenAI calls without per-user or per-org budgets.
